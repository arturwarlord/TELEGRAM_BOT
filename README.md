# Deal Hunter — автоматический бот выгодных скидок

Бот собирает **конкретные товарные карточки со скидкой из публично доступных каталогов магазинов**. Режим проекта — **только прямые ссылки на карточки товаров**, без партнёрских редиректов, tracking-ссылок и обязательного участия в партнёрских программах. Купоны и промокоды полностью исключены. Товары публикуются с фотографией, явно указанными старой и новой ценой и прямой ссылкой продавца. Авиабилеты Aviasales остаются отдельным типом предложений. **Автоматическая публикация выполняется по расписанию GitHub Actions**; изменения кода и обычные push запускают только dry-run.

## Текущий режим

- Сбор источников запускается каждые 30 минут. **Запуски по расписанию публикуют автоматически**; обычные push и тестовые запуски остаются в **dry-run**.
- Все товарные публикации используют `product_url` — прямую публичную ссылку продавца. `ALLOW_DIRECT_LINKS=true` включён для всех режимов; известные партнёрские/редирект-домены отбрасываются фильтром URL.
- Takprodam Publisher API в активном workflow **отключён**: секрет и настройки партнёрского источника больше не передаются GitHub Actions. Даже если токен остался в настройках репозитория, код игнорирует его, пока явно не задан `ENABLE_TAKPRODAM_PARTNER_API=true`.
- Для товарной публикации обязательны конкретная карточка товара, фотография и явная пара старой и текущей цены. Старую цену бот не вычисляет из процента скидки. Авиабилеты публикуются отдельно и не выдаются за товарную скидку.
- Текущие пороги из `config/settings.json`: скидка на товар не меньше 10%, экономия не меньше 50 ₽; предложения с подозрительно большой скидкой выше 90% исключаются.
- Цены, наличие и условия доставки могут зависеть от региона, выбранного магазина, карты лояльности и аккаунта покупателя. Перед покупкой нужно проверить финальную цену у продавца.
- Источники подключаются только при наличии разрешённого публичного доступа и корректно извлекаемых карточек. CAPTCHA, 401/403/429, блокировки и TLS-ошибки не обходятся. Каталог источников — список кандидатов, а не обещание охвата буквально каждого сервиса РФ.
- Проект использует стандартную библиотеку Python — сторонние пакеты не требуются.

## Источники, которые сканируются

В `config/sources.json` сейчас **378 записей источников: 124 включены, 254 выключены**. Среди включённых — **120 конфигураций Aviasales Data API** по городам вылета и несколько публичных страниц магазинов/путешествий. Купонные типы и категории среди включённых источников отсутствуют. В каталоге **146 записей помечены для read-only диагностики**; эта метка может сочетаться с другими полями конфигурации. Выключенные страницы не участвуют в публикации: часть возвращает ошибки доступа, антибот-проверки, TLS-ошибки либо не содержит пригодных карточек. Защита сайтов не обходится.

### Активные источники

- **Товарные скидки:** только публичные страницы «ВкусВилл», «Республика» и «Мир Хобби» с прямыми ссылками. «Республика» и «Мир Хобби» уже проходили live-проверку и отдавали конкретные товарные карточки; «ВкусВилл» пока нестабилен: диагностика находила карточки, но production scan возвращал 0.
- **Путешествия и авиабилеты:** Aviasales Data API по 120 городам вылета и Avianity — статьи с конкретными предложениями авиабилетов. Цена билета показывается как ориентировочная; авиабилеты не выдаются за скидку на товар.
- **Партнёрские/купонные каталоги:** не используются в активном режиме. Из старых конфигураций они могут оставаться в файле как отключённые кандидаты, но не участвуют в сборе и публикации.

**Важно для билетов:** для фактической загрузки данных нужно добавить секрет GitHub Actions `AVIASALES_API_TOKEN` из профиля Travelpayouts. Без секрета код корректно пропускает вызовы API и выводит предупреждение; реальных цен на билеты в таком запуске нет. [Официальная документация Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API) описывает кэшированные данные цен и специальные предложения по авиабилетам. Бот не придумывает старую цену или процент скидки, если API их не предоставляет.

**Важно для туров:** endpoint `/v3/get_special_offers` используется для авиабилетов, а не как API пакетных туров. Для авиабилетов используем Aviasales Data API; официальная документация указывает, что данные цен формируются из кэшированных поисков, поэтому цену нужно перепроверять перед публикацией. Для пакетных туров добавлены отдельные кандидаты: Level.Travel, Travelata, Большая Страна, YouTravel, Tourvisor, Слетать.ру, Coral Travel, Sunmar, FUN&SUN, OnlineTours, TEZ TOUR, Pegas Touristik, Интурист, Алеан и Дельфин. Они не публикуются автоматически, пока не подтвердится извлечение конкретного тура, цены, изображения и прямой ссылки. Доступ к официальным API/фидам Travelata и Level.Travel может требовать индивидуального одобрения партнёрской программы; это не заменяется Aviasales API. Новые официальные страницы Т-Путешествий проверены, но оставлены выключенными: GitHub Actions не смог подтвердить TLS-цепочку сертификатов, поэтому проверка сертификатов не отключалась.

### Почему не подключены общие каталоги Ozon, Wildberries и X5

- **Ozon:** официальный Statistics API действительно описывает данные по большому ассортименту и ценам, но доступ внешним аналитическим сервисам предоставляется на коммерческой основе. Отдельные условия Ozon на получение данных запрещают передавать такие данные третьим лицам, даже бесплатно. Поэтому мы не используем этот набор данных для публикаций в открытом Telegram-канале без отдельного письменного разрешения на такое распространение. [Официальное описание Statistics API](https://dev.ozon.ru/news/256-Novyi-API-dlia-polucheniia-dannykh-Statistics-API/).
- **Wildberries:** публичная документация WB API начинается с регистрации в кабинете продавца и описывает инструменты управления товарами, ценами, остатками, продвижением и заказами продавца. Это не открытый API всего потребительского каталога. [Документация WB API](https://dev.wildberries.ru/).
- **Пятёрочка:** публичный раздел «Выгодно» показывает товары, цены и прямые URL карточек. Но GitHub Actions получает HTTP 403 для этой страницы; поэтому источник оставлен выключенным. Персональные акции X5 Клуба формируются индивидуально и показываются в приложении, поэтому их нельзя выдавать за общую скидку для всех покупателей. [Каталог «Выгодно»](https://5ka.ru/catalog/vygodno--251C17047/) · [описание персональных акций](https://5ka.ru/personaloffers/).

Пока отсутствует разрешённый и стабильно доступный в GitHub Actions источник, карточка маркетплейса не добавляется в автопубликацию. Не используем скрытые endpoints, не обходим HTTP 403/498 или антибот-защиту и не публикуем ссылки-переадресации.

## Takprodam / Admitad — не используется в прямом режиме

Интеграция Takprodam сохранена в кодовой базе как прежний эксперимент, но **активный workflow её не вызывает** и не получает `TAKPRODAM_API_TOKEN`. Это сделано намеренно: текущая задача — собирать товарные предложения из публичных источников без участия в партнёрской программе и без tracking-ссылок.

Чтобы случайно не активировать интеграцию, одного наличия старого секрета `TAKPRODAM_API_TOKEN` недостаточно. Вызов требует отдельного явного флага `ENABLE_TAKPRODAM_PARTNER_API=true`; в рабочем workflow этот флаг не задан. Публикация в Telegram в любом случае использует только публичный URL товара.

## Дополнительные источники RSS/XML/JSON

Откройте `config/sources.json` и добавьте объект в массив `sources`:

```json
{
  "name": "Название партнёрского фида",
  "type": "xml",
  "enabled": true,
  "url": "https://адрес-выданного-партнёром-фида.example/feed.xml",
  "links_are_affiliate": true
}
```

Поддерживаемые типы: `rss`, `xml`, `json`. Для JSON-фида по умолчанию ожидается массив объектов или поле `items`. Если фид содержит отдельное поле партнёрской ссылки, бот предпочтёт его. `links_are_affiliate: true` указывайте **только** для фида, в котором URL товаров уже являются вашими партнёрскими ссылками.

Можно переопределить названия полей через `fields`, например:

```json
"fields": {
  "title": ["name", "product_name"],
  "product_url": ["url", "product_link"],
  "affiliate_url": ["tracking_link", "affiliate_link"],
  "image_url": ["picture", "image"],
  "price": ["sale_price", "price"],
  "old_price": ["old_price", "regular_price"],
  "store": ["merchant", "shop"]
}
```

Сначала запустите workflow вручную с `publish = false`. В логах появятся найденные предложения и причины отсева. Не включайте публикацию, пока фид и партнёрские ссылки не проверены.

## Настройка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Добавьте бота администратором канала с правом публикации сообщений.
3. В GitHub откройте **Settings → Secrets and variables → Actions**.
4. В **Secrets** добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
5. В **Variables** добавьте:
   - `TELEGRAM_CHAT_ID` — `@имя_канала` для публичного канала или числовой ID частного канала;
   - `AD_NOTICE` — например: `Партнёрская ссылка: канал может получить вознаграждение за покупку.`. Не заменяет обязательную юридическую маркировку, если она требуется. Если API оффера передаёт `legal_text`, бот включает и его.

Не вставляйте токен в код, конфигурацию или логи.

### Проверка Telegram без тестового сообщения

После настройки секрета и переменных открой **Actions → Telegram Setup Check → Run workflow**. Этот workflow проверит токен через `getMe`, найдёт канал через `getChat` и подтвердит права через `getChatMember`. Он не отправляет сообщений. Успешная проверка должна показать имя бота, канал и право `can_post_messages`.

Если канал публичный, значение `TELEGRAM_CHAT_ID` обычно имеет вид `@имя_канала`. Для частного канала понадобится его числовой ID. Бот должен быть администратором канала с включённым правом **Post Messages**.

## Настройка GitHub Actions

Workflow **Deal Hunter** запускается по расписанию каждые 30 минут и вручную.

- Сканирование работает каждые 30 минут. Запуски по расписанию публикуют автоматически; обычные push и тестовые запуски остаются в dry-run. В direct-link режиме комиссия каналу не начисляется.
- Для пробного запуска: **Actions → Deal Hunter → Run workflow → publish = false**.
- Ручной запуск с `publish = true` публикует подходящие предложения: с партнёрской ссылкой, если она есть, иначе с публичной ссылкой источника. Нужны рабочие источники, Telegram secret, chat ID и текст `POST_NOTICE` или `AD_NOTICE` для партнёрских постов. Для обычных публичных ссылок используется встроенная пометка об отсутствии комиссии.
- Автопубликация по расписанию включена по умолчанию с лимитом не более 15 постов за запуск и 80 постов за любые 24 часа. Чтобы временно приостановить публикации, задайте Actions Variable `DRY_RUN = true`; удалите переменную или установите `false`, чтобы возобновить публикации.

Состояние опубликованных сделок сохраняется в `data/state.json`, чтобы уменьшать количество повторов. По умолчанию бот публикует не более 15 постов за один запуск и не более 80 постов за любые 24 часа. Повторная публикация возможна при существенном падении цены или после длительного интервала с улучшением цены. Workflow автоматически коммитит этот файл после успешной публикации.

## Партнёрская аналитика отключена

Отдельный workflow отчёта комиссий Takprodam удалён из активных GitHub Actions. В прямом режиме бот не запрашивает партнёрские комиссии, не использует tracking-ссылки и не отправляет партнёрские публикации.

## Проверки

Локально или в GitHub Actions:

```bash
python -m unittest discover -s tests -v
python main.py
```

Тесты используют фиктивные данные и не отправляют сообщения в Telegram.

## Что важно перед запуском на аудиторию

- Начните с партнёрских фидов, доступ к которым одобрен партнёрской сетью или магазином.
- Сравнение «старая цена / новая цена» считается доказанным только при наличии обеих цен в данных источника. Бот не объявляет размер скидки, если цены отсутствуют или старая цена не выше новой.
- Картинка должна идти из разрешённого источником фида/материалов.
- Для коммерческих постов проверьте требования партнёрской программы, маркировки рекламы, реквизитов рекламодателя и ERID, если применимо к вашему рынку. В РФ требования зависят от правового режима и площадки; текстовая пометка о партнёрской ссылке сама по себе не гарантирует соблюдение всех правил.
- Некоторые программы платят баллами или требуют проверки поста — это не следует считать денежной комиссией без проверки условий.

## Этапы развития

1. Основа: источники, оценка скидки, Telegram-публикатор, дедупликация и тесты.
2. Подключение одобренной площадки Takprodam/Admitad Publisher API и проверка качества данных.
3. Расширение источников по маркетплейсам, продуктам и ресторанам, включая дополнительные партнёрские сети.
4. История цен, антифрод, статистика переходов и конверсий там, где партнёр предоставляет такие данные.

### Приоритизация авиабилетов

В рейтинге Aviasales приоритет получают вылеты из российских городов; вылеты из стран СНГ также получают умеренный приоритет над дальними иностранными аэропортами. Цена по-прежнему влияет на оценку, а международные предложения не исключаются. Это улучшает релевантность верхних карточек для русскоязычного канала без выдумывания скидок.
