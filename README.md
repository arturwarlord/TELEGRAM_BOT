# Deal Hunter — автоматический бот выгодных скидок

Бот собирает скидки, промокоды и распродажи из публичных страниц магазинов и сервисов РФ, фильтрует предложения по явным условиям, убирает дубли и может публиковать в Telegram карточки с изображением и ссылкой на страницу предложения. Сейчас канал наращивает каталог и аудиторию **без партнёрских ссылок и без комиссии**: в прямом режиме кнопка ведёт на публичную страницу магазина/акции.

## Текущий режим

- Сбор источников запускается каждые 30 минут; по умолчанию сканирование работает в **dry-run** и не публикует посты.
- Для публикации без партнёрки используется `ALLOW_DIRECT_LINKS=true`: если у источника есть tracking URL, бот всё равно использует обычную публичную ссылку из `product_url`.
- Для товарных скидок бот требует явные старую и новую цену; для промокодов — только явно опубликованный код и/или процент. Цены не придумываются.
- Изображение обязательно для публикации. Устаревшие предложения с известной датой окончания отбрасываются; повторы ограничиваются состоянием публикаций.
- Текущие пороги из `config/settings.json`: скидка на товар не меньше 25%, экономия не меньше 50 ₽; для купонов минимум 10%, максимум заявленной скидки — 90%.
- Цены, наличие и промокоды могут зависеть от города, карты лояльности, новых/повторных заказов и минимальной суммы корзины. Канал не получает комиссию в direct-link режиме.
- Источники должны предоставлять данные законно и в соответствии со своими правилами. Каталог источников — расширяемый список, а не обещание охвата буквально каждого сервиса РФ.
- Проект использует стандартную библиотеку Python — сторонние пакеты не требуются.

## Источники, которые сканируются

В `config/sources.json` сейчас **232 записи источников: 141 включён, 91 отключён/на проверке**. Среди включённых — **21 публичный HTML-источник** и **120 конфигураций официального Aviasales Data API** по городам вылета. Отключённые страницы не участвуют в рассылке: часть возвращает ошибки доступа, антибот-проверки, TLS-ошибки либо не содержит пригодных карточек. Защита сайтов не обходится.

### Активные источники

- **Каталоги промокодов и скидок:** ПромоФакт, БериКод, Promocodex, О Скидках, Скидометр, BonusOK, DonCoupon, CouponMagic, **Промокодик** и **Picodi**.
- **Официальные акции и товарные карточки:** «Детский мир», «Четыре Лапы», «ВкусВилл» и «Магнит».
- **Путешествия, отели, авиабилеты и туры:** три раздела БериКод (путешествия/туры, билеты/транспорт, бронирование/отели), Тут-Билеты, Тревелинка и **Авианити**. Авианити теперь разбирается отдельным парсером свежих статей с конкретной ценой авиабилета; извлекаются только статьи за последние 3 дня с изображением, полученным со страницы самой статьи. Эти источники также дают промокоды и описание условий, а не гарантируют цену на любую дату. В подборку локальных предложений добавлен КупиКупон (Москва).
- **Авиабилеты Aviasales:** **120 конфигураций городов вылета** в России, СНГ, популярных аэропортах Турции, ОАЭ, Юго-Восточной Азии, Европы, Северной Америки и других направлений. Список IATA-кодов и настройки каждой точки вылета находится в `config/sources.json`.

**Важно для билетов:** для фактической загрузки данных нужно добавить секрет GitHub Actions `AVIASALES_API_TOKEN` из профиля Travelpayouts. Без секрета код корректно пропускает вызовы API и выводит предупреждение; реальных цен на билеты в таком запуске нет. [Официальная документация Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API) описывает кэшированные данные цен и специальные предложения по авиабилетам. Бот не придумывает старую цену или процент скидки, если API их не предоставляет.

**Важно для туров:** endpoint `/v3/get_special_offers` используется для авиабилетов, а не как API пакетных туров. Промокоды на туры, отели и транспорт собираются отдельно из активных туристических каталогов. Новые официальные страницы Т-Путешествий проверены, но оставлены выключенными: GitHub Actions не смог подтвердить TLS-цепочку сертификатов, поэтому проверка сертификатов не отключалась.

### Последний подтверждённый dry-run — 28 октября 2026 года

- Скан загрузил **306 записей**, после удаления дублей осталось **262 уникальных предложения**.
- **176 предложений** прошли действующие фильтры скидки, срока действия и качества.
- Takprodam API вернул **51 товар со скидкой**; новый парсер Авианити добавил **4 свежих предложения на авиабилеты** с изображениями, Picodi дал около **20 карточек**, «Промокодик» — **5**, а КупиКупон — **58 предложений** с локальными услугами Москвы.
- Автоматический набор тестов: **91 тест пройден**. В этом dry-run Telegram не вызывался, посты не публиковались.

Счётчики показывают результаты парсинга, а не ручную проверку каждого предложения в корзине. Цена и доступность билета/тура могут зависеть от дат, города, карты лояльности, минимальной суммы, типа покупателя и условий продавца. Перед покупкой нужно проверить финальную цену на сайте продавца.

### Что было проверено, но отключено

В числе кандидатов — Купоника, GoodCoupon, Promokodus, Promokodo, Сравни, Arrivo, Promokodoff, Samokatus, страницы Т-Путешествий, Tutu, S7, Аэрофлота, Островка, Яндекс Путешествий, «Победы», РЖД, а также каталоги Ozon, «Перекрёстка», METRO, «Ленты», О’КЕЙ, «Лемана ПРО», «Ашана», DNS, Спортмастера и туристических операторов.

- **Купоника** теперь читается с правильной кодировкой Windows-1251, однако конкретные карточки всё ещё не проходят парсер. Не включается до улучшения извлечения товарных карточек.
- **КупиКупон** включён после read-only проверки: парсер нашёл 58 предложений с конкретными страницами и изображениями. Это преимущественно локальные предложения Москвы, а не общероссийские товары.
- **Arrivo, Promokodoff, Выберу, Samokatus и дополнительные каталоги** оставлены отключёнными: текущий парсер не извлекает достаточно надёжную связку «конкретное предложение — корректная ссылка — изображение», либо видит JS-кнопки и связанные статьи. В конфиге остаются **3 кандидата с диагностическим флагом**; они не участвуют в публикации до отдельной проверки. Никакие коды и цены не выдумываются.
- **Picodi** включён после проверки: рабочий парсер находит 20 карточек и использует уникальные якоря на публичной странице. Карточки с кредитами, займами, казино и ставками исключаются.
- **GoodCoupon** отдаёт страницу проверки бота; **Promokodo** — HTTP 403; страницы Т-Путешествий возвращали TLS-ошибку. Эти ограничения не обходятся.
- Дополнительно проверены 8 кандидатов: главная Tutu и страница скидки на ж/д билеты (0 пригодных карточек), S7 (403), Аэрофлот (страница ограничения доступа), Островок и «Победа» (404), Яндекс Путешествия (проверка «Вы не робот?»), РЖД (тайм-аут). Все они сохранены выключенными с причиной; антибот-проверки и TLS-защита не обходятся.
- Некоторые официальные магазины отвечают 401/403/450, ограничивают частоту запросов или показывают редирект вместо каталога. Такие источники включаются только после успешной проверки разметки.

Это осознанный фильтр качества: лучше оставить источник выключенным, чем опубликовать ложную скидку, нерабочий промокод или ссылку на неподходящий товар. После изменений запускаются автоматические тесты и [Public Deal Source Diagnostics](https://github.com/arturwarlord/TELEGRAM_BOT/actions/workflows/source-diagnostics.yml). Диагностические кандидаты не участвуют в публикации.

## Основной источник: Takprodam / Admitad Publisher API

Последний dry-run успешно получил **51 товар со скидкой** из источника `24285`; фильтр `marketplace` исправлен на формат API-slug (`ozon`, `wildberries`). Публикация всё равно использует публичные прямые ссылки в текущем режиме и не включается обычным push-запуском. Официальный API может возвращать список товаров, акции и промокоды, цену до скидки, цену по акции, процент скидки, комиссию, фото, tracking-ссылку и текст рекламной маркировки. Документация: [Takprodam Publisher API](https://support.admitad.ru/article/ru/259-api-dlya-pablishera.html?product=R5WidLdNoV7Iyw0a).

1. Зарегистрируйтесь в [Takprodam](https://takprodam.ru/api-publisher/) и подключите доступ к Publisher API.
2. Добавьте публичный Telegram-канал в источники/площадки в партнёрском кабинете, вставьте предоставленный код/текст подтверждения в описание канала и дождитесь статуса **approved**. По инструкции поддержки проверка обычно занимает до 48 часов; если статус остаётся `verification` дольше 48 часов после добавления, обратитесь в `support@takprodam.ru`. [Инструкция для паблишеров](https://admitadru.useresponse.com/knowledge-base/article/%D0%BA%D0%B0%D0%BA-%D0%BD%D0%B0%D1%87%D0%B0%D1%82%D1%8C-%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D1%83-%D1%81-%D1%82%D0%B0%D0%BA%D0%BF%D1%80%D0%BE%D0%B4%D0%B0%D0%BC_1).
3. В личном кабинете откройте **Профиль → Общие настройки профиля → Генерация API токена**.
4. В GitHub откройте **Settings → Secrets and variables → Actions → Secrets** и добавьте секрет `TAKPRODAM_API_TOKEN` с токеном API. Никогда не публикуйте токен в файлах, логах или сообщениях.
5. В **Variables** необязательно задайте:
   - `TAKPRODAM_SOURCE_ID` — ID нужной одобренной площадки. Если у аккаунта ровно одна одобренная площадка, бот попробует выбрать её автоматически; если несколько — ID нужно указать.
   - `TAKPRODAM_MARKETPLACES` — список через запятую, по умолчанию `Ozon,Wildberries`.
   - `TAKPRODAM_LIMIT` — размер страницы, не больше 1000; по умолчанию `1000`.
   - `TAKPRODAM_MAX_PAGES` — число страниц на маркетплейс, от 1 до 10; по умолчанию `1`;
   - `TAKPRODAM_SUBID` — метка источника трафика, по умолчанию `telegram_deal_hunter`. Она нужна для отделения статистики этого бота от других источников. API использует `subid` при формировании ссылок и позволяет фильтровать по нему комиссии.

Если токен не задан, этот источник просто пропускается. Если площадка не одобрена, бот не пытается использовать её как действующую.

## Дополнительные источники RSS/XML/JSON

Откройте `config/sources.json` и добавьте объект в массив `sources`:

```json
{
  "name": "Название партнёрского фида",
  "type": "xml",
  "enabled": true,
  "url": "https://адрес-выданного-партнёром-фида.example/feed.xml",
  "links_are_affiliate": true
}
```

Поддерживаемые типы: `rss`, `xml`, `json`. Для JSON-фида по умолчанию ожидается массив объектов или поле `items`. Если фид содержит отдельное поле партнёрской ссылки, бот предпочтёт его. `links_are_affiliate: true` указывайте **только** для фида, в котором URL товаров уже являются вашими партнёрскими ссылками.

Можно переопределить названия полей через `fields`, например:

```json
"fields": {
  "title": ["name", "product_name"],
  "product_url": ["url", "product_link"],
  "affiliate_url": ["tracking_link", "affiliate_link"],
  "image_url": ["picture", "image"],
  "price": ["sale_price", "price"],
  "old_price": ["old_price", "regular_price"],
  "store": ["merchant", "shop"]
}
```

Сначала запустите workflow вручную с `publish = false`. В логах появятся найденные предложения и причины отсева. Не включайте публикацию, пока фид и партнёрские ссылки не проверены.

## Настройка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Добавьте бота администратором канала с правом публикации сообщений.
3. В GitHub откройте **Settings → Secrets and variables → Actions**.
4. В **Secrets** добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
5. В **Variables** добавьте:
   - `TELEGRAM_CHAT_ID` — `@имя_канала` для публичного канала или числовой ID частного канала;
   - `AD_NOTICE` — например: `Партнёрская ссылка: канал может получить вознаграждение за покупку.`. Не заменяет обязательную юридическую маркировку, если она требуется. Если API оффера передаёт `legal_text`, бот включает и его.

Не вставляйте токен в код, конфигурацию или логи.

### Проверка Telegram без тестового сообщения

После настройки секрета и переменных открой **Actions → Telegram Setup Check → Run workflow**. Этот workflow проверит токен через `getMe`, найдёт канал через `getChat` и подтвердит права через `getChatMember`. Он не отправляет сообщений. Успешная проверка должна показать имя бота, канал и право `can_post_messages`.

Если канал публичный, значение `TELEGRAM_CHAT_ID` обычно имеет вид `@имя_канала`. Для частного канала понадобится его числовой ID. Бот должен быть администратором канала с включённым правом **Post Messages**.

## Настройка GitHub Actions

Workflow **Deal Hunter** запускается по расписанию каждые 30 минут и вручную.

- Сканирование работает каждые 30 минут. Публикация не начинается автоматически, пока в Actions не включён publish-режим. В direct-link режиме комиссия каналу не начисляется.
- Для пробного запуска: **Actions → Deal Hunter → Run workflow → publish = false**.
- Ручной запуск с `publish = true` публикует подходящие предложения по обычным ссылкам магазинов. Нужны рабочие источники, Telegram secret, chat ID и текст `POST_NOTICE` (если он пуст, применяется встроенная заметка о прямой ссылке и отсутствии комиссии).
- Автопубликация по расписанию включена по умолчанию с лимитом не более 2 постов за запуск и 8 постов за любые 24 часа. Чтобы временно приостановить публикации, задайте Actions Variable `DRY_RUN = true`; удалите переменную или установите `false`, чтобы возобновить публикации.

Состояние опубликованных сделок сохраняется в `data/state.json`, чтобы уменьшать количество повторов. По умолчанию бот публикует не более 2 постов за один запуск и не более 8 постов за любые 24 часа. Повторная публикация возможна при существенном падении цены или после длительного интервала с улучшением цены. Workflow автоматически коммитит этот файл после успешной публикации.

## Отчёт по партнёрским комиссиям

Workflow [Takprodam Commission Report](https://github.com/arturwarlord/TELEGRAM_BOT/actions/workflows/takprodam-commission-report.yml) запускается вручную и ежедневно. Он читает комиссионные записи, отфильтрованные по `TAKPRODAM_SUBID`, и показывает количество и суммы по статусам `pending`, `approved` и `declined`. Он не публикует сообщения и не изменяет данные партнёрского кабинета.

Необязательные Actions Variables:
- `TAKPRODAM_REPORT_LIMIT` — записей на страницу, по умолчанию `1000`;
- `TAKPRODAM_REPORT_MAX_PAGES` — максимум страниц, по умолчанию `5`.

До одобрения площадки и появления переходов/заказов отчёт может быть пустым — это не ошибка само по себе.

## Что важно перед запуском на аудиторию

- Начните с партнёрских фидов, доступ к которым одобрен партнёрской сетью или магазином.
- Сравнение «старая цена / новая цена» считается доказанным только при наличии обеих цен в данных источника. Бот не объявляет размер скидки, если цены отсутствуют или старая цена не выше новой.
- Картинка должна идти из разрешённого источником фида/материалов.
- Для коммерческих постов проверьте требования партнёрской программы, маркировки рекламы, реквизитов рекламодателя и ERID, если применимо к вашему рынку. В РФ требования зависят от правового режима и площадки; текстовая пометка о партнёрской ссылке сама по себе не гарантирует соблюдение всех правил.
- Некоторые программы платят баллами или требуют проверки поста — это не следует считать денежной комиссией без проверки условий.

## Этапы развития

1. Основа: источники, оценка скидки, Telegram-публикатор, дедупликация и тесты.
2. Подключение одобренной площадки Takprodam/Admitad Publisher API и проверка качества данных.
